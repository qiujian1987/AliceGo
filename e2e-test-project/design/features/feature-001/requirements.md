# 笔记管理特性需求规约

## 1. 特性基本信息

- **特性ID**：feature-001
- **特性名称**：笔记管理特性
- **所属模块**：个人笔记应用
- **优先级**：高
- **负责人**：@backend-dev / @frontend-dev
- **创建日期**：2026-05-17

## 2. 用户故事

- 作为**用户**，我要**创建笔记**，以便**记录我的想法和信息**
- 作为**用户**，我要**查看所有笔记列表**，以便**快速了解我记录的所有内容**
- 作为**用户**，我要**查看单条笔记详情**，以便**仔细阅读特定笔记的完整内容**
- 作为**用户**，我要**编辑笔记**，以便**修改或补充已记录的笔记内容**
- 作为**用户**，我要**删除笔记**，以便**移除不需要的笔记**

## 3. 功能需求

### 3.1 创建笔记

- **FR-001-001**：用户可以创建新的笔记
- **FR-001-002**：笔记包含标题（必填）和内容（必填）
- **FR-001-003**：创建笔记时自动生成创建时间
- **FR-001-004**：新创建的笔记ID自动递增

### 3.2 查看笔记列表

- **FR-001-005**：用户可以查看所有笔记的列表
- **FR-001-006**：笔记列表按创建时间倒序排列（最新在前）
- **FR-001-007**：列表显示笔记标题、创建时间和摘要（前100字符）

### 3.3 查看笔记详情

- **FR-001-008**：用户可以查看单条笔记的完整内容
- **FR-001-009**：详情页面显示标题、内容、创建时间和更新时间

### 3.4 编辑笔记

- **FR-001-010**：用户可以修改笔记的标题和内容
- **FR-001-011**：编辑时自动更新更新时间戳
- **FR-001-012**：编辑前需要验证笔记是否存在

### 3.5 删除笔记

- **FR-001-013**：用户可以删除指定的笔记
- **FR-001-014**：删除前需要确认（防止误删）
- **FR-001-015**：删除后返回成功状态

## 4. 数据需求

### 4.1 数据实体

- **Note（笔记）**：
  - id: INTEGER (主键, 自增)
  - title: TEXT (标题, 必填, 最大255字符)
  - content: TEXT (内容, 必填)
  - category: TEXT (分类标签, 可选, 默认空字符串)
  - created_at: DATETIME (创建时间, 自动生成)
  - updated_at: DATETIME (更新时间, 自动生成)

### 4.2 数据关系

- 一个笔记属于一个分类（可选）
- 一个分类可以包含多个笔记（可选）

### 4.3 数据格式

- 标题：UTF-8编码字符串，最大255字符
- 内容：UTF-8编码文本，无长度限制
- 时间：ISO 8601格式（YYYY-MM-DDTHH:mm:ssZ）

## 5. 界面需求

### 5.1 笔记列表页面

- 页面布局：顶部标题栏 + 笔记列表 + 底部操作栏
- 笔记卡片显示：标题、创建时间、分类标签、内容摘要
- 操作按钮：新增笔记按钮（悬浮在右下角）

### 5.2 笔记详情页面

- 页面布局：顶部返回按钮 + 笔记内容 + 底部操作栏
- 操作按钮：编辑按钮、删除按钮

### 5.3 笔记编辑页面

- 页面布局：顶部保存按钮 + 表单（标题输入框、内容输入框）
- 表单验证：标题和内容不能为空

## 6. 验收标准

- **AC-001-001**：用户能够成功创建包含标题和内容的笔记
- **AC-001-002**：用户能够在笔记列表页面看到所有笔记
- **AC-001-003**：用户能够点击笔记查看完整内容
- **AC-001-004**：用户能够编辑已有笔记的标题和内容
- **AC-001-005**：用户能够删除不需要的笔记
- **AC-001-006**：所有操作后页面状态正确更新

## 7. 技术约束

### 7.1 性能要求

- 笔记列表加载时间 < 1秒
- 单条笔记查询时间 < 500ms
- 创建/更新/删除操作响应时间 < 800ms

### 7.2 安全要求

- 防止SQL注入攻击（使用参数化查询）
- 防止XSS攻击（对用户输入进行转义）
- 验证输入数据长度和格式

### 7.3 兼容要求

- 支持主流浏览器：Chrome、Firefox、Safari、Edge
- 响应式设计，适配桌面和移动设备

## 8. 依赖关系

### 8.1 前置依赖

- 无（这是基础功能，其他功能依赖此特性）

### 8.2 后置依赖

- feature-002（分类管理）：需要基于笔记添加分类功能
- feature-003（搜索功能）：需要基于笔记实现搜索

### 8.3 外部依赖

- SQLite 数据库：用于存储笔记数据
- Express.js + TypeScript：后端技术栈
- React + TypeScript：前端技术栈

## 9. 风险与假设

### 9.1 潜在风险

- SQLite 数据库在大量数据时可能需要优化查询
- 前端富文本编辑器可能影响笔记内容显示

### 9.2 假设条件

- 假设用户熟悉基本的Web操作
- 假设笔记内容不会包含恶意代码

### 9.3 应对策略

- 对数据库查询进行优化，添加必要索引
- 对用户输入进行严格的验证和转义
