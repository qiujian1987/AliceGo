# 搜索功能特性需求规约

## 1. 特性基本信息

- **特性ID**：feature-003
- **特性名称**：搜索功能特性
- **所属模块**：个人笔记应用
- **优先级**：中
- **负责人**：@backend-dev / @frontend-dev
- **创建日期**：2026-05-17

## 2. 用户故事

- 作为**用户**，我要**根据关键词搜索笔记**，以便**快速找到包含特定内容的笔记**

## 3. 功能需求

### 3.1 关键词搜索

- **FR-003-001**：用户可以在搜索框输入关键词进行搜索
- **FR-003-002**：搜索范围包括笔记标题和内容
- **FR-003-003**：搜索结果实时显示（输入时自动搜索）
- **FR-003-004**：搜索结果高亮显示匹配的关键词

### 3.2 搜索结果展示

- **FR-003-005**：搜索结果以列表形式展示
- **FR-003-006**：每个结果显示标题、内容摘要和匹配位置
- **FR-003-007**：显示搜索结果总数
- **FR-003-008**：无搜索结果时显示友好提示

### 3.3 搜索优化

- **FR-003-009**：支持模糊匹配（如"笔记"可以匹配"笔记本"）
- **FR-003-010**：忽略大小写进行搜索
- **FR-003-011**：搜索性能优化，响应时间 < 1秒

## 4. 数据需求

### 4.1 搜索索引

- **Note索引**：
  - 标题索引：FULLTEXT索引
  - 内容索引：FULLTEXT索引

### 4.2 搜索算法

- 使用SQLite的FULLTEXT搜索功能
- 支持布尔模式搜索（可选）
- 支持通配符搜索（可选）

### 4.3 数据格式

- 搜索关键词：UTF-8编码字符串
- 匹配结果：显示标题和内容片段（前后50字符）

## 5. 界面需求

### 5.1 搜索入口

- 搜索框：页面顶部固定位置
- 搜索图标：放大镜图标，点击展开搜索框
- 搜索历史：显示最近5次搜索记录（可选）

### 5.2 搜索结果页面

- 结果列表：显示匹配的笔记列表
- 结果高亮：关键词以高亮方式显示
- 结果统计：显示"找到X条结果"
- 无结果提示：友好提示"未找到相关笔记"

### 5.3 搜索交互

- 实时搜索：输入时自动搜索（防抖300ms）
- 清空搜索：提供清空按钮
- 关闭搜索：点击空白处或返回按钮关闭搜索

## 6. 验收标准

- **AC-003-001**：用户能够通过关键词搜索找到匹配的笔记
- **AC-003-002**：搜索结果能够正确显示在列表中
- **AC-003-003**：搜索能够匹配标题和内容
- **AC-003-004**：无搜索结果时显示友好提示
- **AC-003-005**：搜索响应时间 < 1秒
- **AC-003-006**：搜索忽略大小写

## 7. 技术约束

### 7.1 性能要求

- 搜索响应时间 < 1秒
- 支持至少1000条笔记的搜索
- 搜索操作不应影响其他功能

### 7.2 安全要求

- 防止SQL注入攻击（使用参数化查询）
- 防止XSS攻击（搜索结果需要转义）
- 限制搜索关键词长度（最大100字符）

### 7.3 兼容要求

- 支持主流浏览器
- 响应式设计

## 8. 依赖关系

### 8.1 前置依赖

- **feature-001（笔记管理）**：必须在搜索功能之前实现，因为需要先有笔记才能搜索

### 8.2 后置依赖

- 无（搜索是独立功能）

### 8.3 外部依赖

- SQLite 数据库（FULLTEXT搜索支持）
- Express.js + TypeScript
- React + TypeScript

## 9. 风险与假设

### 9.1 潜在风险

- SQLite的FULLTEXT搜索功能有限
- 大量数据时搜索性能可能下降
- 中文分词问题（SQLite默认不支持中文分词）

### 9.2 假设条件

- 假设笔记数量不会超过10000条
- 假设用户主要使用英文或拼音搜索

### 9.3 应对策略

- 对搜索字段添加FULLTEXT索引
- 实现防抖机制减少不必要的搜索请求
- 考虑未来升级到支持中文分词的数据库
