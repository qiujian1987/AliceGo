# 个人笔记应用需求规约

## 1. 项目概述

- **项目名称**：个人笔记应用
- **项目目标**：创建一个简单易用的个人笔记应用，用于验证 AliceGo 框架的端到端流程
- **目标用户**：个人用户，需要简单的方式记录和管理笔记

## 2. 业务需求

- 提供笔记的创建、查看、编辑和删除功能
- 支持笔记的分类管理
- 提供笔记搜索功能
- 强调简单性和易用性

## 3. 功能需求

### 3.1 笔记管理

- **创建笔记**：用户可以创建新的笔记，包括标题和内容
- **查看列表**：用户可以查看所有笔记的列表
- **查看详情**：用户可以查看单条笔记的详细信息
- **编辑笔记**：用户可以修改已有笔记的标题和内容
- **删除笔记**：用户可以删除不需要的笔记

### 3.2 分类管理

- **添加标签**：用户可以为笔记添加分类标签
- **按分类筛选**：用户可以按照分类标签筛选笔记列表

### 3.3 搜索功能

- **关键词搜索**：用户可以根据关键词搜索笔记
- **搜索范围**：搜索应覆盖笔记的标题和内容

## 4. 非功能需求

### 4.1 技术栈

- **后端**：
  - Express.js + TypeScript
  - SQLite 数据库
  - RESTful API 设计
- **前端**：
  - React + TypeScript
  - 简洁的用户界面

### 4.2 测试要求

- 单元测试覆盖率 ≥ 80%
- 集成测试覆盖核心功能

### 4.3 质量要求

- 代码通过 lint 检查
- 代码通过 type check
- 所有 API 都有对应的测试用例

## 5. 范围

### 5.1 包含

- 笔记的 CRUD 操作
- 分类标签管理
- 笔记搜索功能
- 前后端交互 API
- 单元测试和集成测试

### 5.2 不包含

- 用户认证和授权
- 云端同步
- 笔记分享功能
- 笔记导出功能

## 6. 验收标准

1. **笔记 CRUD**：用户可以成功创建、查看、编辑和删除笔记
2. **分类筛选**：用户可以按分类标签筛选笔记列表
3. **搜索功能**：用户可以根据关键词搜索笔记
4. **测试覆盖**：所有 API 都有对应的测试用例
5. **代码质量**：代码通过 lint 和 type check

## 7. 风险

- 搜索功能可能影响性能（需要索引优化）
- SQLite 在高并发场景下性能有限（但适合个人使用场景）
- 测试覆盖率目标（≥80%）需要良好的代码架构支持

## 8. 假设与约束

- 假设：用户熟悉 Web 应用的基本操作
- 约束：使用 SQLite 数据库，适合单用户场景
- 约束：使用 TypeScript，确保类型安全
- 约束：需要兼容主流浏览器

## 9. 数据模型

### 9.1 笔记 (Note)

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 主键，自增 |
| title | TEXT | 笔记标题 |
| content | TEXT | 笔记内容 |
| category | TEXT | 分类标签 |
| created_at | DATETIME | 创建时间 |
| updated_at | DATETIME | 更新时间 |

### 9.2 API 端点

| 方法 | 端点 | 说明 |
|------|------|------|
| GET | /api/notes | 获取所有笔记 |
| GET | /api/notes/:id | 获取单条笔记 |
| POST | /api/notes | 创建笔记 |
| PUT | /api/notes/:id | 更新笔记 |
| DELETE | /api/notes/:id | 删除笔记 |
| GET | /api/notes/search?q=keyword | 搜索笔记 |
