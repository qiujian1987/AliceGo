# PROB-005: Agent、Skills、Rules职责边界混淆

## 基本信息
- **问题ID**: PROB-005
- **记录时间**: 2026-05-25
- **项目名称**: AliceGo
- **问题类型**: 架构问题

## 问题描述

### 现象
在调优过程中发现：
- Agent提示词中包含了执行流程、格式规范等应该放在Skill中的内容
- Skill中包含了应该在Rules中定义的约束条件
- 三者职责边界不清晰，导致维护困难
- 修改某个功能时，不知道应该改Agent还是Skill还是Rules

### 影响范围
- 所有Agent和Skill的维护
- 新功能开发时的职责分配
- 团队协作效率
- 系统可维护性

### 严重程度
**高** - 影响系统架构的清晰性和可维护性

## 原因分析

### 根本原因
1. **职责定义不明确**：没有明确定义Agent、Skill、Rules各自的职责边界
2. **初始设计考虑不周**：初始时没有考虑三者的职责划分原则
3. **调优过程随意**：调优时哪里方便就在哪里改，没有遵循职责划分

### 触发条件
- 需要修改某个流程时
- 需要添加新功能时
- 新成员入职需要理解系统时

## 解决方案

### 最终方案
明确三者职责边界：

**Agent的职责**：
- 角色定义："是谁"和"做什么"
- 协作规范：如何与其他Agent协作
- 输入输出：接收什么参数，返回什么结果
- 不包含具体的执行流程和格式规范

**Skill的职责**：
- 执行流程："怎么做"的具体步骤
- 输出格式："输出什么"的具体规范
- 业务逻辑：具体的业务处理逻辑
- 工具调用：如何调用具体的工具

**Rules的职责**：
- 约束条件：必须遵守的规则
- 标准规范：编码规范、命名规范等
- 流程定义：项目的整体流程
- 验证标准：什么是"正确"的标准

### 实施步骤
1. 梳理所有Agent提示词，将执行流程迁移到对应Skill
2. 梳理所有Skill，将约束条件迁移到Rules
3. 更新 AGENTS.md，明确各Agent与Skill的对应关系
4. 编写职责边界文档，指导后续开发

## 预防措施

### 技术手段
- 在 AGENTS.md 中明确记录每个Agent的职责和对应的Skill
- 在 Skill 的 SKILL.md 开头明确说明该Skill的职责
- 在 Rules 中明确记录所有约束条件

### 流程改进
- 新增功能时，先确定职责归属：是Agent？是Skill？还是Rules？
- 修改功能时，先确认应该在哪个层面修改
- Code Review时，检查职责边界是否清晰

### 检查点
- [ ] 新增功能前，确定职责归属
- [ ] Code Review时，检查职责边界
- [ ] 定期回顾，确保职责清晰
