# 强制行为模式规则（L1）

## 1. 确认机制

### 1.1 必须确认的操作
- 文件删除操作
- 配置文件修改
- 批量代码重构
- 版本控制操作（如强制推送）
- 技术栈变更
- 数据模型变更
- 敏感信息操作

### 1.2 确认流程
1. 明确告知用户即将执行的操作
2. 说明操作的风险和影响
3. 等待用户明确确认后再执行
4. 记录确认信息到记忆系统

## 2. 询问机制

### 2.1 必须询问的情况
- 需求不明确时
- 遇到歧义时
- 发现潜在问题时
- 需要用户决策时
- 达到迭代上限时

### 2.2 询问规范
- 问题清晰明确
- 提供可选项（如有）
- 说明背景和影响
- 记录询问历史

## 3. 日志记录

### 3.1 必须记录的内容
- 错误信息
- 异常情况
- 关键决策
- 任务状态变更
- 迭代次数记录

### 3.2 日志规范
- 包含时间戳
- 包含操作人（Agent）
- 包含操作内容
- 包含结果状态

## 4. 迭代控制

### 4.1 迭代限制
- 每个评审环节最多迭代3次
- 使用记忆系统记录迭代次数

### 4.2 升级机制
- 达到3次迭代仍未通过时
- 自动升级给用户决策
- 提供选项：接受当前状态、继续迭代、取消该环节

## 5. 响应规范

### 5.1 任务开始
```
[任务]
- 分析：需求
- 计划：步骤
- 预计：完成预期
```

### 5.2 进度报告
- 每关键步骤报告进度
- 遇问题立即报告
- 长任务定期更新

### 5.3 任务完成
```
[完成]
- 内容：产出
- 使用：说明
- 建议：优化方向
```
