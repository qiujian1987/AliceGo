# Loop Budget 预算控制规则（L2）

## 1. 概述

本规则定义了AliceGo项目中的Budget预算控制体系，包括每步token预算上限、单任务最大迭代次数、项目级总预算阈值，以及预算耗尽时的自动降级或终止策略。

## 2. 目标

- **资源约束**：防止Agent无限重试或过度消耗token资源
- **成本控制**：在保证质量的前提下控制AI使用成本
- **自动预警**：预算即将耗尽时自动通知用户
- **智能降级**：预算耗尽时自动采取降级策略，而非直接终止

## 3. 预算层级

### 3.1 项目级预算

```json
{
  "project_id": "proj-001",
  "total_budget_tokens": 1000000,
  "consumed_tokens": 0,
  "remaining_tokens": 1000000,
  "budget_alert_threshold": 0.2,
  "budget_critical_threshold": 0.1
}
```

| 字段 | 说明 | 默认值 |
|------|------|--------|
| `total_budget_tokens` | 项目总token预算 | 1,000,000 |
| `consumed_tokens` | 已消耗token数 | 0 |
| `remaining_tokens` | 剩余token数 | 等于总预算 |
| `budget_alert_threshold` | 预警阈值（剩余比例） | 0.2（20%） |
| `budget_critical_threshold` | 临界阈值（剩余比例） | 0.1（10%） |

## 4. 迭代次数限制

### 4.1 单步骤迭代次数

| 步骤类型 | 最大迭代次数 | 说明 |
|---------|------------|------|
| 评审步骤（步骤4/12/17/21） | 3次 | 已在03_workflow.md中定义 |
| 开发步骤（步骤20/22） | 3次 | 代码生成和修改的重试次数 |
| 设计步骤（步骤8/9/10/11） | 2次 | 架构设计的重试次数 |
| 其他步骤 | 1次 | 确认步骤等无重试 |

### 4.2 项目级迭代次数

- **总评审迭代次数**：最多12次（4个评审步骤 × 3次）
- **总开发迭代次数**：最多6次（2个开发步骤 × 3次）
- **总设计迭代次数**：最多8次（4个设计步骤 × 2次）

## 5. 预算预警机制

### 5.1 预警级别

| 级别 | 条件 | 动作 |
|------|------|------|
| **正常** | 剩余预算 > 20% | 无特殊动作 |
| **预警** | 剩余预算 ≤ 20% 且 > 10% | 通知用户，建议关注成本 |
| **临界** | 剩余预算 ≤ 10% | 通知用户，启用降级策略 |

### 5.2 预警通知

当达到预警阈值时，系统自动发送通知：

```
⚠️ 预算预警
- 项目：{项目名称}
- 当前阶段：{阶段名称}
- 已消耗：{consumed_tokens} token
- 剩余：{remaining_tokens} token（{percentage}%）
- 建议：考虑优化需求范围或增加预算
```

## 6. 降级策略

当预算达到临界阈值时，系统自动执行降级策略：

### 6.1 降级策略层次

| 层级 | 策略 | 说明 |
|------|------|------|
| **Level 1** | 跳过非核心特性 | 只完成核心功能，非核心特性标记为后续迭代 |
| **Level 2** | 简化设计 | 使用更简单的架构方案，减少设计复杂度 |
| **Level 3** | 减少测试覆盖 | 将测试覆盖率目标从95%降至80% |
| **Level 4** | 人工介入 | 暂停自动流程，请求用户决策 |

### 6.2 降级执行流程

```
1. 检测预算达到临界阈值
2. 自动发送预警通知
3. 根据当前阶段选择降级策略：
   - 需求阶段 → Level 1（跳过非核心特性）
   - 设计阶段 → Level 2（简化设计）
   - 开发阶段 → Level 3（减少测试覆盖）
4. 执行降级策略
5. 继续流程直到完成或用户干预
```

## 7. 预算状态追踪

### 7.1 状态字段

项目状态文件中增加以下字段：

```json
{
  "budget": {
    "total": 1000000,
    "consumed": 150000,
    "remaining": 850000,
    "alert_level": "normal",
    "current_stage_allocation": 250000,
    "stage_consumed": 80000,
    "stage_remaining": 170000
  }
}
```

### 7.2 预算更新时机

| 时机 | 更新内容 |
|------|---------|
| 步骤开始前 | 记录当前预算状态 |
| 步骤完成后 | 更新已消耗token数 |
| 回退时 | 不扣除回退步骤的预算 |
| 迭代时 | 每次迭代单独计数 |

## 8. 配置说明

### 8.1 配置文件位置

预算参数可通过以下方式配置：

1. **默认配置**：本规则文件中定义的默认值
2. **项目配置**：`design/project_overview/budget_config.json`
3. **运行时配置**：通过自然语言输入覆盖

### 8.2 自定义配置示例

```json
{
  "project_budget_overrides": {
    "total_budget_tokens": 2000000,
    "budget_alert_threshold": 0.3,
    "budget_critical_threshold": 0.15
  },
  "stage_budget_overrides": {
    "development": 0.6
  }
}
```

## 9. 验证机制

### 9.1 预算验证检查

每步执行前必须检查：

1. 项目级预算是否充足
2. 当前阶段预算是否充足
3. 当前步骤预算是否充足
4. 是否达到预警或临界状态

### 9.2 验证失败处理

| 失败类型 | 处理方式 |
|---------|---------|
| 步骤预算不足 | 跳过该步骤，标记为待人工处理 |
| 阶段预算不足 | 执行降级策略 |
| 项目预算不足 | 暂停流程，请求用户决策 |
