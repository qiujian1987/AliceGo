# TRAE Harness 端到端推演测试规范

## Why

验证 AliceGo 框架是否能够正常从需求开始，通过 SOLO Coder 调度各个 Agent，Agent 能否正常调用 Skills，完成整个项目从 0-1 的构建。发现框架中的问题和优化点。

## What Changes

- 创建一个简单的测试项目（如：个人笔记应用）
- 从需求分析开始，验证完整28步流程
- 验证 Agent 调度是否正常
- 验证 Agent 调用 Skill 是否正常
- 记录每个步骤的执行情况
- 生成推演报告，指出问题和优化点

## Impact

- Affected: 整个 AliceGo 框架
- 验证: 28步流程执行、Agent调度、Skill调用

##### 评审环节迭代验证

在每个评审环节（步骤4、12、17、21）验证：
- 评审不通过时，迭代计数是否正确
- 迭代达到3次时，是否正确升级用户决策
- 评审通过时，是否正确进入下一步

### 核心验证点

### 1. Agent 调度验证
- SOLO Coder 是否能正确识别需要调用的 Agent
- Agent 标识（如 @architect）是否能被正确解析
- Agent 之间的切换是否顺畅
- HANDOFF 规范是否被正确执行

### 2. Agent 调用 Skill 验证
- Agent 是否能正确调用对应的 Skill
- Skill 是否能被正确触发
- Skill 输出是否符合预期
- Skill 之间的依赖关系是否正确

### 3. 流程执行验证
- 28步流程是否被正确执行
- 评审环节是否被正确触发
- 验证检查点是否被执行
- 用户确认节点是否被正确处理

## 输出产物

生成推演报告：`推演报告_YYYYMMDD.md`

内容包括：
1. 推演概述
2. 完整执行步骤记录（28步）
3. Agent调度验证结果
4. Skill调用验证结果
5. **评审迭代循环验证结果**
6. 问题发现
7. 优化建议

### 评审迭代循环验证标准

每个评审环节（步骤4、12、17、21）需要验证：

1. **迭代触发**：评审不通过时，系统是否正确触发迭代
2. **迭代计数**：迭代次数是否被正确记录（通过 mcp_Memory）
3. **迭代上限**：迭代达到3次时，是否正确升级给用户决策
4. **评审通过**：评审通过时，是否正确进入下一步
