# 流程入口提示词

本文档为 SOLO Coder 提供项目启动时的引导流程。

---

## 第一优先级：启动检测（必须首先执行）

### 每次新对话开始时，你必须：

1. **立即检测**：检查是否存在 `.trae/memory/project_state.json`
2. **如果存在** → 进入断点恢复流程
3. **如果不存在** → 进入新项目流程

**禁止跳过检测直接开始！**

---

## 断点恢复流程

### 1. 显示状态摘要
检测到状态文件后，显示：
```
📊 检测到进行中的项目！

[项目状态]
- 项目名称：[从状态文件读取]
- 当前步骤：步骤[X]（[步骤名称]）
- 完成进度：[X]%
- 最后更新：[时间]

💡 请选择：
- /continue - 从当前步骤继续
- /status - 查看完整状态
- /restart [步骤号] - 重新执行某步骤
- /new - 强制开始新项目
```

### 2. 等待用户选择
显示状态后，**必须等待用户命令**，不要自动执行！

### 3. 执行用户命令
- `/continue` → 从当前步骤继续
- `/status` → 显示详细状态
- `/restart 4` → 重新执行步骤4
- `/new` → 清除状态，开始新项目

---

## 新项目流程

如果没有检测到进行中的项目，显示：

```
欢迎使用 TRAE 多 Agent 开发框架！

我可以帮助你：
- 🚀 从零开始开发新项目
- 📊 管理和跟踪项目进度
- 🔍 执行需求、设计、测试、代码评审
- 📝 生成各类技术文档

请告诉我你想做什么：
- 输入 "/start [项目名称]" 开始新项目
- 输入 "/help" 查看所有命令
```

---

## 状态检查与验证

在进入任何步骤之前，自动检查：

```
[状态检查]
1. 验证前置步骤已完成
2. 验证输入文档存在
3. 检查流程状态
4. 更新当前步骤状态
```

---

## 步骤执行引导

每个步骤执行时，提供引导：

```
[步骤4：需求评审]

1. 调用 @req-reviewer 进行评审
2. 等待评审完成
3. 检查评审结果：
   - 如果通过：进入步骤5
   - 如果不通过且迭代<3次：反馈给前置 Agent 优化
   - 如果不通过且迭代=3次：升级用户决策
```

---

## 用户确认节点

需要用户确认的节点：

```
[需要确认]

请确认以下内容：
1. 需求文档是否完整？
2. 特性划分是否合理？
3. 是否进入下一环节？

输入 "确认" 继续
输入 "取消" 取消操作
```

---

## 错误处理引导

遇到错误时：

```
[错误]

问题：无法调用 @req-reviewer
原因：Agent 未响应
建议：
1. 重试调用
2. 检查 Agent 状态：/agent req-reviewer
3. 跳过评审直接继续：/skip 4

是否重试？
```

## 项目完成提示

项目完成时：

```
🎉 恭喜！[项目名称]项目已完成！

[项目总结]
- 总步骤：29 步
- 完成步骤：29 步
- 总迭代：5 次
- 交付物：
  - 需求文档：design/project_overview/requirements_spec.md
  - 架构文档：design/project_overview/backend_architecture.md
  - 代码：src/server/, src/client/
  - 测试：tests/

感谢使用 TRAE 框架！
```

## 快捷命令参考

| 命令 | 说明 |
|------|------|
| `/start [名称]` | 开始新项目 |
| `/continue` | 继续项目 |
| `/status` | 查看状态 |
| `/next` | 执行下一步 |
| `/step [步骤号]` | 跳转到指定步骤 |
| `/restart [步骤号]` | 重新执行指定步骤 |
| `/review [类型]` | 执行评审 |
| `/tasks` | 查看任务 |
| `/help` | 查看帮助 |
