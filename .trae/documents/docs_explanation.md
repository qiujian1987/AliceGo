# docs 目录文件作用说明

## 概述

docs 目录下的文件是 AliceGo 框架的**参考文档**，主要面向两类用户：

1. **最终用户**：学习如何使用 AliceGo 框架进行项目开发
2. **框架维护者**：了解框架的内部机制和规范

---

## 文件分类与作用

### 1. 入门指南（getting-started/）

**面向：所有用户**

| 文件 | 作用 | 使用场景 |
|------|------|----------|
| solo-agent-config.md | 指导用户配置 SOLO Agent | 用户首次使用时阅读 |
| mcp-server-config.md | 指导用户配置 MCP Server | 需要扩展 Agent 能力时阅读 |

**使用方式**：
```
用户打开文档 → 按照步骤配置 → 开始使用框架
```

### 2. 指南文档（guides/）

**面向：进阶用户和开发者**

| 文件 | 作用 | 使用场景 |
|------|------|----------|
| design-standards.md | 定义设计标准和最佳实践 | 进行架构设计时参考 |
| review-feedback.md | 定义评审反馈流程 | 执行评审时参考 |

**使用方式**：
```
开发者进行设计或评审时 → 查阅指南 → 遵循标准进行工作
```

### 3. 参考文档（reference/）

**面向：框架维护者和高级开发者**

| 文件 | 作用 | 使用场景 |
|------|------|----------|
| memory-system.md | 记忆系统的设计说明 | 理解状态持久化机制 |
| skill-invocation.md | Skill 的调用规范 | 开发新 Skill 时参考 |
| team-lead-scheduler.md | 团队调度器说明 | 理解任务分配机制 |

**使用方式**：
```
框架维护者 → 查阅参考文档 → 理解内部机制 → 扩展框架功能
```

### 4. 核心文档（根目录）

**面向：所有用户**

| 文件 | 作用 | 使用场景 |
|------|------|----------|
| README.md | 文档目录导航 | 了解有哪些文档可用 |
| commands.md | 命令参考手册 | 用户需要查看可用命令时 |
| file-ownership.md | Agent 领地划分规范 | 避免文件冲突 |
| flow-entry.md | 流程入口提示词 | SOLO Coder 使用的引导文案 |
| memory-usage.md | 记忆系统使用规范 | Agent 开发时参考 |
| project-initialization.md | 项目初始化规范 | DevOps Agent 使用 |
| framework-progress.md | 框架构建历史记录 | 了解框架演进过程 |

**使用方式**：
```
用户输入命令时 → 查阅 commands.md 获取帮助
Agent 执行任务时 → 遵循 file-ownership.md 避免冲突
SOLO Coder 启动时 → 使用 flow-entry.md 的引导文案
```

## 哪些是真正必需的？

### ⭐ 核心必需文件（缺少会影响功能）

| 文件 | 原因 |
|------|------|
| commands.md | SOLO Coder 需要它来解析命令 |
| file-ownership.md | Agent 需要它来避免文件冲突 |
| flow-entry.md | SOLO Coder 需要它来引导用户 |
| memory-usage.md | Agent 需要它来正确使用记忆系统 |
| project-initialization.md | DevOps Agent 需要它来初始化项目 |

### ✨ 推荐保留文件（提升使用体验）

| 文件 | 原因 |
|------|------|
| getting-started/* | 帮助用户快速上手 |
| guides/* | 提供最佳实践指导 |
| reference/* | 帮助开发者理解框架 |
| README.md | 文档导航入口 |

### 📋 可选归档文件

| 文件 | 原因 |
|------|------|
| framework-progress.md | 历史记录，不影响当前功能 |

---

## 总结

这些 docs 文件的作用是：

1. **指导用户**：帮助用户了解如何使用框架
2. **规范行为**：为 Agent 提供操作规范
3. **提供参考**：为开发者提供设计参考
4. **引导交互**：为 SOLO Coder 提供引导文案

它们不像代码那样直接执行，但它们是框架正常运行和用户有效使用的重要支撑。

如果你觉得某些文档确实没有价值，我们可以讨论是否需要精简或合并。
