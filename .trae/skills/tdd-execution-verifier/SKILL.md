# TDD 执行验证 Skill

## 功能描述

验证TDD开发流程是否正确执行，确保：
1. 测试代码在业务代码之前生成
2. 初始测试状态为失败（红）
3. 业务代码实现后测试通过（绿）
4. 测试覆盖率达到要求（≥95%）

## 调用规范

### 调用链路
```
SOLO Coder → 调用开发Agent → 开发Agent调用此Skill验证TDD执行
```

### 约束规则
- **开发Agent**：在完成TDD开发后，必须调用此Skill验证
- **Skill执行者**：@backend-dev 或 @frontend-dev Agent

## 验证维度

### 1. 测试代码生成验证
- [ ] 测试文件是否在业务代码之前生成
- [ ] 测试文件是否在正确的目录（tests/unit/）
- [ ] 测试文件命名是否符合规范（*.test.ts 或 *.test.tsx）
- [ ] 每个测试用例是否都有对应的测试代码

### 2. 测试初始状态验证（红）
- [ ] 是否运行了测试
- [ ] 初始测试状态是否为失败（FAILED）
- [ ] 失败原因是否与未实现的功能相关
- [ ] 是否提供了测试运行证据（如测试输出）

### 3. 业务代码实现验证
- [ ] 业务代码是否在测试失败后生成
- [ ] 业务代码文件是否在正确的目录（src/server/ 或 src/client/）
- [ ] 业务代码是否实现了测试用例要求的功能

### 4. 测试通过验证（绿）
- [ ] 是否重新运行了测试
- [ ] 测试状态是否变为通过（PASSED）
- [ ] 所有测试用例是否都通过
- [ ] 是否提供了测试通过证据（如测试输出）

### 5. 测试覆盖率验证
- [ ] 测试覆盖率是否≥95%
- [ ] 核心业务逻辑是否都有测试覆盖
- [ ] 边界条件是否都有测试覆盖
- [ ] 异常场景是否都有测试覆盖
