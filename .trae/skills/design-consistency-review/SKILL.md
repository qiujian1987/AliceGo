# 设计与开发实现一致性评审 Skill

## 功能描述

检查开发实现与设计文档的一致性，确保开发完全按照架构设计、API设计、数据模型设计等要求进行，避免实现与设计脱节。

## 调用规范

### 调用链路
```
SOLO Coder → 调用 @code-reviewer Agent → @code-reviewer Agent调用此Skill
```

### 约束规则
- **SOLO Coder**：必须先调用@code-reviewer Agent，**禁止**直接调用此Skill
- **@code-reviewer Agent**：负责调用此Skill执行设计一致性评审
- **Skill执行者**：@code-reviewer Agent

## 评审维度

### 1. 架构设计一致性
- [ ] 模块划分是否遵循架构设计文档
- [ ] 数据流是否按照设计要求实现
- [ ] 技术选型是否与架构设计一致
- [ ] 分层架构是否清晰（Controller/Service/Dao/Repository等）
- [ ] 设计模式应用是否符合架构要求

### 2. API设计一致性
- [ ] API端点路径是否与设计文档一致
- [ ] HTTP方法（GET/POST/PUT/DELETE）是否正确
- [ ] 请求参数是否包含设计文档中要求的所有字段
- [ ] 响应格式是否与API契约一致
- [ ] 错误码和错误消息是否符合设计规范
- [ ] 认证授权机制是否按设计实现

### 3. 数据模型一致性
- [ ] 数据库表结构是否与设计文档一致
- [ ] 字段名称、类型、长度是否符合规范
- [ ] 索引是否按设计要求创建
- [ ] 外键关系是否正确实现
- [ ] 数据验证规则是否按设计实现
- [ ] 字段约束（非空、唯一等）是否完整

### 4. 前端设计一致性
- [ ] 页面结构是否遵循前端架构设计
- [ ] 组件复用是否符合设计系统要求
- [ ] 路由设计是否与设计一致
- [ ] 状态管理是否按设计实现
- [ ] UI组件库使用是否规范

### 5. 接口契约一致性
- [ ] 前后端数据传输格式是否符合API契约
- [ ] 字段命名大小写是否一致
- [ ] 数据类型是否匹配
- [ ] 必填字段验证是否完整
- [ ] 枚举值范围是否符合设计
